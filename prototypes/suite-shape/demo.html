Prototype — throwaway

What shape should a Suite artifact take?

The question: a deck test is a Suite of deterministic Checks generated at Build start from the Brief and the Format profile (ADR 0003). What artifact form should that Suite take so it reads and runs in both runtimes — claude.ai chat (code-execution sandbox, pasted data, no repo) and Claude Code (files on disk)? Where do Role tags and profile targets live so an Upgrade re-run stays stable? And what does the red/green report look like as a Block? Everything below runs one real fixture: Sunlit Flock, a Kitchen 20 white lifegain Pack built from genuine Foundations card data (Scryfall).

The three candidate shapes

A — rendered checklist

Markdown the model walks, counting by hand. Runs anywhere — even with no sandbox — but every re-run trusts model arithmetic, and drift is invisible. In this prototype A is generated from C (check_deck.py --render-checklist), so it is a degraded view, not a source of truth.

B — bespoke generated script

A one-off script whose targets, Role tags, and thresholds are hardcoded (candidate-b-bespoke.py). Deterministic — but the Suite is code, so an Upgrade regenerates ~150 lines and hopes only the Brief-shaped parts changed.

C — declarative Suite + fixed runner

The Suite is data (suite.yaml): targets, quotas, Role tags, check ids. A fixed runner shipped with the skill (check_deck.py, stdlib-only) interprets any Suite. This page re-implements the same runner in JavaScript — two interpreters, one artifact.
